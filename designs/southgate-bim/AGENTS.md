# AGENTS.md - Southgate Worship Center BIM (native IFC)

Rules for Claude Code, Codex and any other automated agent. Concept design: **NOT FOR CONSTRUCTION.**

## 1. Sources of truth

| What | Authoritative file | Notes |
|---|---|---|
| Construction information (elements, materials, quantities, relationships) | `bim/southgate.ifc` | IFC4. Edit through Bonsai or the IfcOpenShell API only. |
| Visualisation (cameras, lights, render settings) | `bim/visualisation.blend` | Holds **no building geometry**. Never treat it as a model. |
| Design source the IFC was migrated from | `source/snapshot/southgate_source_snapshot_20261107.blend` (read-only, sha256 in `source/source_manifest.json`) | Copy of `../F-site-A-2000-astra-v2/model/church_auditorium_2000.blend`. |
| Source object -> IFC identity | `source/source_to_ifc_mapping.csv` | Stable IDs and GlobalIds. Never renumber. |

There must never be two independently editable copies of construction truth. If you edit the IFC in Bonsai,
do not also "fix" the same thing in the source `.blend` or in a migration rule, or the next rebuild will overwrite it
(see section 4).

## 2. Never

- Write to anything in `../F-site-A-2000-astra-v2/`, including its model, scripts and reports. Follow that project's own AGENTS.md if you work there.
- Write to `source/snapshot/` (the file is read-only by design).
- Run historical generator scripts from the old project to "rebuild" geometry.
- Overwrite `bim/southgate.ifc` other than with `build_ifc.py --publish --expected-current-sha256 <sha>`. That command keeps the previous file in `work/published_history/`.
- Raise `SOUTHGATE_DesignStatus.DesignStatus` to `ENGINEERING_VERIFIED` or `APPROVED_FOR_DOCUMENTATION` without written engineering evidence. Record that evidence in the pset.
- Migrate the children's church or other detached buildings. The scope is the main auditorium (`config/project.yaml` -> `boundary`).

## 3. Environment

- Blender 5.2.3 is at `C:\Program Files\Blender Foundation\Blender 5.2\blender.exe`.
- Bonsai 0.9.0-post1 is installed in an isolated Blender profile: set `BLENDER_USER_RESOURCES=%LOCALAPPDATA%\SouthgateBIM\blender_user`. The user's normal Blender profile has no Bonsai, and that is deliberate.
- Python: `.venv` (Python 3.10) with `ifcopenshell==0.9.0.post1` (the same build as Bonsai's) and `ifc5d==0.9.0`.
- Headless Blender: always pass `-b --python-exit-code 1` and check the log for `Traceback`.
- Tests: `.venv/Scripts/python -m pytest -q`.

## 4. Migration pipeline (re-runnable, deterministic)

```
inspect   blender ... snapshot --python scripts/inspect/inventory_source.py   -- --out source/geometry_inventory.json
          blender ... snapshot --python scripts/inspect/export_source_cache.py -- --out work/source_cache.pkl
plan      .venv/Scripts/python scripts/migrate/plan_migration.py [--commit-mapping]   (dry run by default)
build     .venv/Scripts/python scripts/migrate/build_ifc.py --dry-run | [--only SRC...] | (full)
quantify  .venv/Scripts/python scripts/export/extract_quantities.py --in <build>/southgate.ifc --out <build>/southgate_qto.ifc
publish   .venv/Scripts/python scripts/migrate/build_ifc.py --publish --expected-current-sha256 <sha|NONE>
validate  .venv/Scripts/python -I scripts/validate/validate_ifc.py bim/southgate.ifc --out reports/audits/ifc_validation.json
```

- Every build is a clean reconstruction into a new `work/builds/<stamp>_<name>/`. Each phase writes a checkpoint, and that checkpoint is reopened and audited before the next phase starts.
- GlobalIds are uuid5 values derived from stable IDs, so reruns cannot create duplicates.
- A failing phase stops the run, and the published file is untouched.
- **After the model is edited in Bonsai, do not rebuild from the source.** A rebuild discards IFC edits. From then on the IFC is the design. Use the migration pipeline only to re-migrate before edits start, or into a separate build for comparison.

## 5. Editing the IFC

- Use Bonsai's parametric tools. Walls are `Bonsai.DumbLayer2`, slabs are `Bonsai.DumbLayer3`, and members are profile sets. Doors and windows carry `BBIM_Door` / `BBIM_Window` data on their types.
- Save with Bonsai (`bim.save_project`) to a new file first, then publish.
- After any geometry edit, refresh quantities with `extract_quantities.py`. Use `--check` to detect stale stored quantities.
- Keep `SOUTHGATE_Provenance` on migrated elements. New elements need a new stable ID: next free number in the category, and register it in the mapping CSV.

## 6. Reports

`reports/migration/`, `reports/audits/` and `reports/quantities/` are regenerated by `scripts/export/make_reports.py`. Do not hand-edit generated reports. Change the inputs and regenerate instead.
